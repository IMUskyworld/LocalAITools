# AICoding 架构设计 · 开发计划

> 本文档为 MVP（W1~W10）开发落地计划，基于已冻结的六份架构文档（《高层架构设计》《系统设计》《部署设计》《安全设计》《UserStory》《调研报告》）与 GUI 文档。
> 上游边界：高层架构 §4.3 MVP 范围 F1~F11（全 P0）、§1.3 量化指标（V1~V5）、§6.3 功能清单。
> 团队假设：3 人核心团队（LocalMind 1 人 / LocalFile 1 人 / RelayCloud 1 人，shared-contract 共担）；1~5 人可伸缩，1 人团队按阶段串行、窗口拉长 1.5~2 倍。

### 1.2 工程骨架（~1.5 天）

按系统设计 §3.1.4 工程结构搭 monorepo：

```
LocalAITools/
├── localmind/          # Tauri 2.x + React/TS + Rust
├── localfile/          # Kotlin + Compose
├── relay-cloud/        # relay-server(Rust+axum) + gateway-config + ops
├── shared-contract/    # envelope/v1 + error-code + whitelist（三端生成源头）
└── docs/
```

- `shared-contract` 先落：信封 v1 JSON Schema + 错误码注册表 + 白名单枚举，三端代码生成（quicktype/schemars）——这是三端并行的契约基线，必须最先冻结。
- 各端 `cargo`/`gradle`/`package` 依赖锁版本（对齐系统设计 §3.1.5 技术选型表）。
- llama.cpp 按 b4xxx 稳定 tag 拉源码，Windows/Android 双端编译脚本验证通过。

### 1.3 CI/CD 骨架（~1 天）

按部署设计 §4.2 三条流水线（LocalMind / LocalFile / RelayCloud）搭 GitHub Actions：代码检查 + 单测 + 安全扫描 + 构建四阶段先通；红线扫描（0 key 入包）先占位。CD 部署阶段 Phase 3 再接。

**里程碑 M0（W1 末）**：硬伤清零、monorepo 可构建、CI 三线绿灯。

## 2. Phase 1：技术骨架验证（W1 后半 ~ W3，2 周）

> 这是整个项目的 **go/no-go 节点**。三端并行，各自验证最不确定的技术点。文档再细也替代不了手写代码实测——端侧推理吞吐、JNI 稳定性、WSS 时延这三项是"能不能做出来"的真正判官。

### 2.1 LocalMind 骨架（Windows 端）

| 验证项 | 做法 | 达标线 |
| --- | --- | --- |
| llama.cpp FFI 跑通 | Rust 封装 llama-cpp-2 binding，加载 DeepSeek-R1-0528-Qwen3-8B Q4_K_M（5.2GB），流式推理 | 基准设备（16GB 无独显 PC）实测 **≥5 tok/s** |
| 内存占用 | 模型加载后常驻内存 | ≤ 物理内存 70%（留出系统与 GUI） |
| Tauri + WebView2 启动 | 空壳 GUI 冷启动到主界面 | ≤ 3s |
| 在线链路连通 | 经 new-api 调 deepseek-chat，SSE 流式 | 首 token ≤ 1s（网关连通时） |

### 2.2 LocalFile 骨架（Android 端）

| 验证项 | 做法 | 达标线 |
| --- | --- | --- |
| llama.cpp JNI 跑通 | libllama.so 桥接，加载 Qwen3-4B Q4（4GB），流式推理 | 骁龙 8 系旗舰实测 **≥8 tok/s** |
| 设备检测 | ActivityManager 读 RAM + Build 读 SoC，档位匹配规则 | 6GB 机型正确判不达标、12GB 机型正确放行 |
| 中低端机降级 | 6GB 机型下载按钮置灰 + 引导在线 | 无 OOM、无闪退 |
| Compose 冷启动 | 空壳 App 冷启动到首页 | ≤ 3s |

### 2.3 RelayCloud 骨架（云端）

| 验证项 | 做法 | 达标线 |
| --- | --- | --- |
| WSS 中继最小链路 | relay-server 单实例 Docker 部署 + SQLite，配对码签发/核销 + 指令路由 + ACK | 配对 ≤60s；指令端到端 **P95 ≤3s**（不含模型生成） |
| new-api 网关 | Docker 部署 + DeepSeek 渠道 + 模型映射 + 令牌额度 | 在线对话透传正常；0 key 入客户端 |
| 断线重连与幂等 | 端侧断网→重连，commandId 去重 | 补发不产生重复执行 |
| 2C4G 承载 | relay + new-api + Nginx 同机常驻内存 | ≤ 2.5GB（余量给系统） |

### 2.4 骨架阶段风险裁决

任一骨架不达标的处置预案（不静默硬撑）：

| 不达标项 | 处置 |
| --- | --- |
| PC 离线 tok/s < 5 | 降模型档：8B → 4B/3B；或放宽基准设备定义（要求 32GB/独显）；回头改高层架构 V1 |
| Android 离线 tok/s < 8 | 降档 4B → 1.5B/3B；或将"≥8 tok/s"指标降为"≥5 tok/s" |
| JNI 不稳定（崩溃/内存泄漏） | 评估换 llama.rn（PocketPal JSI 方案，系统设计 §3.1.5 已备选） |
| WSS 时延 P95 > 3s | 排查中继实现；极端情况提前从完整版拉 P2P 通道（F14 上提） |
| 2C4G 内存撑不下 | 收紧容器 mem_limit；或升配 4C8G（月账单需重算 ≤150 元红线） |

**里程碑 M1（W3 末）**：三骨架指标全部达标 = go。此时架构技术可行性被代码证实，后续是工程量问题而非可行性问题。

## 4. Phase 3：集成联调与打包（W9 ~ W10，2 周）

### 4.1 集成联调（W9）

- int 环境（部署设计 §2.1，prod 云主机逻辑隔离）双端真机联调；
- 三大演示场景端到端跑通（高层架构 §4.3 MVP 退出标准）：
  1. PC 在线 + 离线对话（含模式切换不丢会话）；
  2. 手机文件 AI 处理（摘要/翻译/重命名，在线 + 离线）；
  3. 手机远程操控电脑执行 ≥5 类白名单指令（含危险动作二次确认）；
- 演示可靠性：连续 10 次配对+连接成功 ≥9 次（V2）。

### 4.2 打包交付（W10）

- LocalMind exe 打包（NSIS + WebView2 引导），体积 ≤80MB，冷启动 ≤3s；
- LocalFile apk 打包签名，体积 ≤60MB，冷启动 ≤3s；
- 构建红线扫描：0 个真实 key / 真实模型名入包（V3 / US-14 AC-3）；
- 首启体验：默认在线模式、网关连通自检、无网时离线引导（US-14）。

### 4.3 指标验收

| 指标 | 目标 | 来源 |
| --- | --- | --- |
| 离线推理吞吐 | PC ≥5 tok/s / Android ≥8 tok/s | V1 |
| 配对建立 | ≤60s；10 次 ≥9 成功 | V2 |
| 远程指令时延 | P95 ≤3s（不含模型生成） | V2/N2 |
| key 零入包 | 0 个 | V3 |
| 安装包体积 | exe ≤80MB / apk ≤60MB | V5/N1 |
| 冷启动 | ≤3s | V5/N1 |
| 云端月账单 | ≤150 元 | §1.3 |

**里程碑 M4（W10 末）**：MVP 交付，三大场景现场可演示，双端安装包可分发，进入答辩/验收。

## 5. 完整版（W11 ~ W16，MVP 验收后）

MVP 骨架是完整版子集（高层架构 §4.3 演进纪律），验收通过后叠加：

- F13 多档模型智能推荐 + 端侧测速页；
- F14 WebRTC P2P 通道（STUN/TURN，中继兜底）+ 桌面截图单帧回传；
- 完整版 E2E 加密（安全设计 D-03）、SQLCipher 端侧库加密（D-04）；
- GUI 🟡档回填功能（联网搜索、文本附件、OCR、剪贴板推送等）按优先级排入。
