## 1. 业务背景与价值

### 1.1 业务背景

- **当前业务现状（行业 / 产品 / 用户规模）**：端侧（on-device）AI 助手品类在 2024~2026 已被商业与开源产品共同验证——桌面端有 LM Studio、Jan，移动端有 Layla、PocketPal AI，远程桌面有 RustDesk；但行业尚无"双端互为延伸 + 对话式远程控制"的端侧优先方案（高层架构 §4.1 差异化价值）。本产品为**校级大学生项目**（课程作业/大创级别），全新产品，无存量系统与存量用户；用户规模为学生开发者本人及小范围同学，分发上限 ≤ 50 人（高层架构 D5 假设）。
- **触发本次需求的事件**：用户需要一套"电脑做桌面 AI 助手、手机做文件处理器兼远程控制器"的双端协同智能工具，AI 能力要求在线（预置云端 API，对用户仅显示"Deepseek-V4-Pro"）与离线（端侧本地大模型一键下载、断网可用）双模；双端经云端服务器协同；最终交付 exe 与 apk 及详尽开发文档用于课程演示与答辩。
- **本系统在产品矩阵中的位置**：独立双端产品，无企业产品矩阵上下文。三组件标准名：**LocalMind**（Windows 桌面 AI 助手）、**LocalFile**（Android 文件处理 + 远程控制器）、**RelayCloud**（云端中继与 API 网关）。LocalMind 是桌面侧 AI 执行体，LocalFile 是移动侧 AI 入口与遥控器，RelayCloud 是二者唯一的会师点（高层架构 §4.1）。

| 标杆系统 | 来源 | 与本项目相关的方案要点 | 本项目借鉴方式 |
| --- | --- | --- | --- |
| B3 Jan（加权 4.45） | Menlo Research，开源 Apache-2.0 | Tauri + React/TS 桌面栈 + llama.cpp 本地推理 + 本地/云端双模 + 本地 OpenAI 兼容 API | 优先借鉴：LocalMind 技术形态与其几乎同构，可代码级借鉴 |

### 1.3 方案收益与价值

| 项 | 说明 |
| --- | --- |
| 功能模块 | ①对话引擎（双端在线/离线双模对话）；②模型管理（一键下载、断点续传、校验、设备检测、模式切换）；③文件处理（Android SAF 浏览 + 摘要/翻译/重命名 + 导出分享）；④远程控制（配对 + 对话式指令通道 + 白名单执行 + 本机二次确认 + 结果回传）；⑤中继调度（WSS 网关 + 设备表 + 指令中转）；⑥API 代理（模型名映射 + 令牌额度管控） |

| 量化标准 | 离线推理吞吐 PC ≥ 5 tok/s、Android ≥ 8 tok/s（V1）；配对 ≤ 60 s、远程指令端到端时延 P95 ≤ 3 s（不含模型生成）、演示 10 次连接成功 ≥ 9 次（V2）；客户端 0 个 key 入包、100% 令牌带额度上限（V3）；下载前设备检测覆盖率 100%、不达标机型降级触达率 100%（V4）；exe ≤ 80MB、apk ≤ 60MB、冷启动 ≤ 3 s（V5）；云端月账单 ≤ 150 元；AI 对话 ≤ 3 步、已配对远程指令 ≤ 2 步（高层架构 §1.3） |

## 5. 用户旅程（UserStory）

> 共 14 条 US。US-1 ~ US-10 覆盖 MVP（F1~F11 全部 P0 功能），US-11 / US-12 为完整版（F13 / F14），US-13 为运维旅程（对应 F12 网关管控看板与 V3 成本目标），US-14 为双端安装交付旅程（对应 D-1 打包交付项）。US 与功能映射汇总见 §5.15。

### 5.1 US-1：LocalMind 在线对话（F1）

#### 5.1.1 业务场景

- **视角**：用户（R2 电脑端使用者）
- **描述逻辑**：工作日在宿舍/图书馆有 Wi-Fi 的环境，R2 打开电脑端 LocalMind，想让 AI 帮忙润色一段实验报告文字。他希望在 3 步之内开始看到流式回答，并且界面只显示"Deepseek-V4-Pro"这一模型名，不需要关心背后的 API。

#### 5.1.2 业务流程

- **视角**：用户
- **描述方式**：
  - **Given** LocalMind 已启动、网络可用、网关连通（顶部状态灯为绿）、当前处于在线模式
  - **When** R2 点击`+ 新对话`，在`消息输入框`输入润色请求并按 Enter
  - **Then** 输入区清空，对话区立即出现用户气泡（右侧）；1 秒内出现 AI 气泡（左侧）并开始打字机式流式输出；AI 气泡下方标注小字"Deepseek-V4-Pro"；状态栏显示网关延迟；生成完成前可随时点击`停止生成`中断

#### 5.1.3 UE 原型

页面：**P-W1 主对话页**（高层架构 §6.4）。核心节点：①顶部`模型模式切换器`当前态高亮"☁ 在线 Deepseek-V4-Pro"；②`连接状态指示灯`绿色，悬停显示"网关已连通 · 延迟 xx ms"；③左侧会话栏新增当前会话条目；④AI 气泡流式打字机渲染，生成中输入区右侧显示`停止生成`按钮；⑤代码块右上角`复制`按钮；⑥底部状态栏显示当前模型名与网关延迟。

#### 5.1.4 业务逻辑

- **视角**：业务系统
- **描述方式**：
  1. 对话引擎模块（LocalMind）接收消息，按当前会话上下文组装 OpenAI 兼容请求，头部携带本设备令牌；
  2. 请求经 HTTPS 发送至 RelayCloud 的 API 代理模块（new-api 网关）；网关校验令牌额度与速率，按模型映射表将显示名"Deepseek-V4-Pro"翻译为 deepseek-chat，注入真实 key 后转发 DeepSeek 官方 API；
  3. DeepSeek 以 SSE 流式返回，网关逐 chunk 透传至客户端，对话引擎增量渲染；
  4. 会话消息落本地存储（会话列表、历史记录仅存在本机）；令牌消耗累计入网关看板；
  5. 令牌额度超限或速率触发时，网关返回标准错误，客户端映射为可读提示。

#### 5.1.5 数据描述

| 数据项 | 流向 | 说明 |
| --- | --- | --- |
| 会话消息（用户输入 + AI 回复） | 客户端内存 → 本地存储（SQLite/文件） | 不上云，云端不留存对话内容 |
| 请求体（messages + model="Deepseek-V4-Pro" + token） | LocalMind → 网关（HTTPS） | 令牌标识设备，不含个人信息 |
| 真实 key + 映射后模型名 | 网关 → DeepSeek（HTTPS） | 仅存在于网关配置，0 个 key 入客户端安装包 |
| SSE 流式响应 | DeepSeek → 网关 → 客户端 | 逐 chunk 透传，无中间落盘 |
| tokens 消耗量 | 网关 → 用量看板 | 供 R4 巡检，对应 V3/月账单 ≤ 150 元 |

#### 5.1.6 验收标准 AC

- **AC-1（正常路径）**：Given 在线模式且网关连通，When 用户发送任意文本消息，Then 1 秒内 AI 气泡出现并开始流式输出，气泡标注"Deepseek-V4-Pro"，全文中不出现 deepseek-chat 或任何真实 API 域名/key 字样。
- **AC-2（会话管理）**：Given 已存在 ≥ 3 个历史会话，When 用户点击左侧任一会话，Then 历史消息完整加载；右键重命名/删除即时生效并持久化，重启应用后仍可见。
- **AC-3（异常路径·网关异常）**：Given 网关不可达（状态灯红），When 用户发送消息，Then 不进入流式等待，3 秒内提示"网关连接异常，可切换离线模式继续使用"，并提供跳转模型管理页入口。
- **AC-4（异常路径·额度耗尽）**：Given 本设备令牌额度已用完，When 用户发送消息，Then 返回可读提示"本设备在线额度已用尽，请联系管理员或切换离线模式"，不暴露 HTTP 状态码与网关内部信息。
- **AC-5（操作步数）**：Given 应用已启动，When 用户从主界面发起一次完整问答，Then 从点击输入到首字输出 ≤ 3 步（点击输入框 → 输入 → Enter）。

#### 5.1.7 外部集成接口

| 依赖 | 内容 |
| --- | --- |
| DeepSeek 官方 API | 经 new-api 网关中转，OpenAI 兼容 `/chat/completions`，SSE 流式；输入 2 元/百万 tokens、输出 8 元/百万 tokens（成本计入 V3 月账单 ≤ 150 元约束） |
| new-api 网关 | 模型映射"Deepseek-V4-Pro"→ deepseek-chat；令牌额度/速率上限 100% 覆盖；异常时返回统一错误格式供客户端映射为可读文案 |

### 5.2 US-2：LocalMind 离线对话与模式切换（F2 + F3 切换部分）

#### 5.2.1 业务场景

- **视角**：用户（R2 电脑端使用者）
- **描述逻辑**：上课教室无 Wi-Fi、热点不稳定，R2 仍要用 AI 总结课件笔记。他已在宿舍下载好本地模型（见 US-3），现在需要在断网状态下切到离线模式继续对话，并随时知道当前吐字速度是否可读。

#### 5.2.2 业务流程

- **视角**：用户
- **描述方式**：
  - **Given** 本地模型已下载且校验通过、本地推理服务已启动（或允许切换时自动启动）、当前网络不可用
  - **When** R2 点击顶部`模型模式切换器`的"⛅ 离线 本地模型"
  - **Then** ≤ 2 次点击完成切换；当前会话不丢失；状态灯变黄（离线模式）；输入区下方出现`当前速度: x.x tok/s`小字；发送消息后本地流式输出，AI 气泡标注"本地模型"

#### 5.2.3 UE 原型

页面：**P-W1 主对话页** + **P-W2 模型管理页**入口。核心节点：①分段切换器当前态变为"⛅ 离线"；②状态灯黄，悬停文案"离线模式 · 本地模型运行中"；③输入区下方 tok/s 实时小字（每秒刷新）；④AI 气泡标注"本地模型"；⑤若本地推理未启动，切换瞬间弹出轻提示"正在启动本地推理…"，就绪后自动完成切换；⑥状态栏显示当前内存占用。

#### 5.2.4 业务逻辑

- **视角**：业务系统
- **描述方式**：
  1. 模式切换请求到达对话引擎模块；引擎查询模型管理模块状态（模型已下载 ✓ / 校验通过 ✓ / 推理服务端口存活）；
  2. 若推理服务未启动，模型管理模块拉起 llama.cpp 本地推理（按 P-W2 推理参数：线程数、上下文长度），就绪回调后完成切换；
  3. 对话引擎将请求路由由"网关链路"切至"本地推理链路"，同一会话上下文直接复用，无需迁移；
  4. 推理 token 流增量渲染并实时计算 tok/s 写入状态区；
  5. 网络恢复后应用**不自动切回**在线（切换是用户显式决策），仅在状态灯恢复绿色可选提示。

#### 5.2.5 数据描述

| 数据项 | 流向 | 说明 |
| --- | --- | --- |
| 会话上下文 | 客户端内存，全程不出设备 | 模式切换仅改路由，不改会话数据 |
| 模型文件（约 5.2GB GGUF） | 本地磁盘 → llama.cpp 内存映射 | 只读加载；SHA256 已在下载时校验 |
| tok/s 指标 | 推理引擎 → UI 状态区 | 仅展示，不上报（完整版测速页才落本地统计） |
| 模式标记（online/offline） | 本地配置存储 | 重启应用后恢复上次模式 |

#### 5.2.6 验收标准 AC

- **AC-1（正常路径）**：Given 模型就绪且断网，When 用户切换到离线模式并发送消息，Then 输出流畅可读，基准设备（16GB 内存无独显 PC）实测 tok/s ≥ 5，全程无任何网络请求发出（可用防火墙断网验证）。
- **AC-2（切换步数）**：Given 任意会话页，When 用户从在线切到离线，Then ≤ 2 次点击完成且当前会话消息列表不丢失、不清空。
- **AC-3（异常路径·模型未下载）**：Given 本地模型未下载，When 用户点击"离线"档，Then 切换被拦截，提示"尚未下载本地模型"，并一键跳转 P-W2 模型管理页下载入口。
- **AC-4（异常路径·推理启动失败）**：Given 本地推理服务拉起失败（实例—端口被占用），When 切换发生，Then 回退到原模式并提示失败原因与"查看详情"（显示端口与建议操作）。
- **AC-5（异常路径·内存不足）**：Given 可用内存不足以加载模型，When 启动推理，Then 应用不崩溃，提示"内存不足，建议关闭其他程序后重试或改用在线模式"，推理服务保持停止状态。

#### 5.2.7 外部集成接口

| 依赖 | 内容 |

### 5.3 US-3：LocalMind 离线模型一键下载（F3 下载部分）

#### 5.3.1 业务场景

- **视角**：用户（R2 电脑端使用者）
- **描述逻辑**：R2 第一次安装 LocalMind，想启用离线模式。他进入模型管理页，看到一个明确的"一键下载"按钮和模型信息（5.2GB），希望点一下就不用管——下载中能看到进度和剩余时间，网络断了也能续传，下完自动校验可用。

#### 5.3.2 业务流程

- **视角**：用户
- **描述方式**：
  - **Given** LocalMind 在线、磁盘剩余空间 ≥ 8GB、当前在 P-W2 模型管理页
  - **When** R2 点击离线模型卡片的`一键下载`
  - **Then** 按钮变为下载控制组：`进度条 + 百分比 + 剩余时间 + 暂停/继续 + 取消`；下载完成自动进行 SHA256 校验；校验通过显示`校验通过 ✓`并提供`删除模型`按钮，模型即可用于 US-2

#### 5.3.3 UE 原型

页面：**P-W2 模型管理页**。核心节点：①离线模型卡片：模型名 DeepSeek-R1-0528-Qwen3-8B Q4_K_M、文件大小 5.2GB、许可标识 MIT；②下载中卡片：实时进度条、百分比、剩余时间估算、瞬时速度；③`暂停/继续`按钮切换下载状态；④校验阶段显示"正在校验文件完整性…"；⑤存储位置行：模型目录路径 + `更改` + `打开文件夹`。

#### 5.3.4 业务逻辑

- **视角**：业务系统
- **描述方式**：
  1. 模型管理模块从预置配置读取模型分发直链（RelayCloud 对象存储/CDN，防盗链签名 URL），创建分块下载任务；
  2. 下载器按分块写入临时文件并记录进度位点，支持暂停（保留位点）与取消（清理临时文件）；
  3. 网络中断或应用重启后，重新进入页面自动检测到未完成位点，提供`继续下载`（断点续传从位点恢复）；
  4. 下载完成读取文件计算 SHA256，与预置清单比对；不一致则删除文件并提示重新下载；
  5. 校验通过写入本地模型清单（名称/版本/路径/校验值），模型状态置为"可用"；磁盘空间不足在点击下载前预检拦截。

#### 5.3.5 数据描述

| 数据项 | 流向 | 说明 |
| --- | --- | --- |
| 模型分发直链（签名 URL） | 客户端预置配置 → 对象存储 | 链接指向 RelayCloud CDN，不指向 HuggingFace 原始域名（国内可达性） |
| 模型文件分块流 | 对象存储 → 本地临时目录 → 模型目录 | 分块校验 + 整文件 SHA256 终验 |
| 进度位点 | 本地状态文件 | 重启可恢复，断点续传依据 |
| 模型清单（元数据 + SHA256） | 预置清单（随安装包） ↔ 本地记录比对 | 许可文本（MIT）随模型卡片展示，满足开源许可合规 |

#### 5.3.6 验收标准 AC

- **AC-1（正常路径）**：Given 网络稳定，When 用户点击`一键下载`，Then 5 秒内开始下载，进度条/百分比/剩余时间实时刷新，完成后自动校验并显示`校验通过 ✓`，一键下载安装成功率 ≥ 95%（V1 目标）。
- **AC-2（断点续传）**：Given 下载进行到 40%，When 网络断开 5 分钟后恢复（或应用被关闭重开），Then 重新进入页面可点击`继续下载`，从约 40% 位点恢复而非从头开始，最终校验通过。
- **AC-3（异常路径·磁盘不足）**：Given 磁盘剩余不足 6GB，When 用户点击`一键下载`，Then 下载被拦截，提示"磁盘空间不足，需要至少 6GB 可用空间"，并提供`更改`存储位置入口。
- **AC-4（异常路径·校验失败）**：Given 下载完成但 SHA256 与清单不一致，When 校验执行，Then 文件被删除，提示"文件校验未通过，请重新下载"，模型状态保持"未下载"。
- **AC-5（异常路径·重复点击）**：Given 下载进行中，When 用户再次点击下载区域，Then 不产生第二个下载任务，界面始终只有一个下载控制组。

| 依赖 | 内容 |
| --- | --- |
| RelayCloud 对象存储 / CDN | 模型文件唯一对客户端分发源；签名 URL 防盗链 + 下载次数限制（成本保护，对应 V3）；源文件由运维从 HuggingFace 镜像/ModelScope 手动同步 |

### 5.4 US-4：LocalMind 本机桌面助手指令执行（F4 本机侧）

#### 5.4.1 业务场景

- **视角**：用户（R2 电脑端使用者）
- **描述逻辑**：R2 在对话中对 LocalMind 说"帮我把下载文件夹里的安装包都删掉"或"打开浏览器"。本地指令执行器收到任务后，只在白名单内动作可直接执行；凡是涉及文件删除、系统设置变更等危险动作，必须先弹窗让他本人确认，执行过程和结果都要留痕可查。

#### 5.4.2 业务流程

- **视角**：用户
- **描述方式**：
  - **Given** LocalMind 运行中，远程控制总开关与本机执行器可用，`危险操作需本机确认`开关为开（默认）
  - **When** R2 在对话输入或`快捷指令`面板发起一条桌面操作请求（实例—"整理桌面文件"）
  - **Then** 执行器解析意图 → 命中白名单常规动作则直接执行并回执结果；命中危险动作则本机弹出二次确认弹窗（指令内容大字 + `允许执行` / `拒绝` + 15 秒倒计时，超时默认拒绝）；执行完毕在对话区与 P-W3 指令执行记录中各留一条含状态的记录

#### 5.4.3 UE 原型

页面：**P-W1 主对话页**（发起）+ **P-W3 远程控制面板页**（设置与记录）。核心节点：①`快捷指令`按钮展开预设面板（总结剪贴板 / 打开应用 / 整理桌面文件等）；②二次确认弹窗：指令内容大字展示、动作类型标识（文件操作/系统设置）、`允许执行`（主按钮）/`拒绝`、15 秒倒计时进度环；③P-W3 安全设置区：`远程控制总开关`、`危险操作需本机确认`开关（默认开）、白名单动作勾选项列表；④指令执行记录列表：时间、来源（本机/设备名）、指令内容、状态（成功/失败/被拦截）。

#### 5.4.4 业务逻辑

- **视角**：业务系统
- **描述方式**：
  1. 对话引擎将用户自然语言解析为结构化指令信封（动作类型 + 参数 + 来源 = 本机）；
  2. 指令执行器先过白名单校验：动作类型 ∉ 白名单 → 直接拒绝并回执"该操作不在允许范围"；
  3. ∈ 白名单且属危险类（文件删除/系统设置变更/应用安装）且确认开关为开 → 触发本机弹窗，等待用户决策（15 秒超时 = 拒绝）；
  4. 允许后调用 OS 能力执行（启动进程 / 文件 API / 系统音量亮度 API），捕获执行结果与错误码；
  5. 全量执行事件写本地执行日志（时间、指令、来源、决策、结果），供 P-W3 记录列表与复盘回路使用。

#### 5.4.5 数据描述

| 数据项 | 流向 | 说明 |
| --- | --- | --- |
| 指令信封（action, params, source, id） | 对话引擎 → 执行器（进程内） | 与远程指令（US-9）共用同一信封格式，完整版叠加加密层 |
| 白名单配置 + 确认开关状态 | 本地配置存储 ↔ 执行器 | 用户在 P-W3 可随时收缩白名单 |
| 执行日志 | 执行器 → 本地日志文件 → P-W3 列表 | 留痕供 R5/本人复盘；`清空记录`可手动清除 |

#### 5.4.6 验收标准 AC

- **AC-1（正常路径·常规动作）**：Given 白名单默认配置，When 用户发起"打开浏览器"，Then 5 秒内浏览器启动，对话区回执"已执行：打开浏览器"，记录列表新增一条"成功"。
- **AC-2（危险动作确认）**：Given 确认开关为开，When 用户发起"删除下载文件夹内所有 exe 文件"，Then 先弹二次确认弹窗，展示完整指令与影响范围；用户点`允许执行`后才执行；点`拒绝`或 15 秒无操作则不执行并记录"被拦截/超时拒绝"。

### 5.6 US-6：LocalFile 离线模型下载与设备检测（F8 下载与检测部分）

#### 5.6.1 业务场景

- **视角**：用户（R3 手机端使用者）
- **描述逻辑**：R3 想让手机也能断网用 AI。他打开"模型与设置"页，先看到一份设备检测报告（RAM、SoC），达标机型直接一键下载约 4GB 模型；他朋友用的 6GB RAM 老手机则被明确告知"建议在线模式"，下载按钮置灰——而不是下完才发现跑不动或直接 OOM 崩溃。

#### 5.6.2 业务流程

#### 5.6.3 UE 原型

页面：**P-A5 模型与设置页**。核心节点：①设备检测卡片（RAM / SoC / 结论文案 + ✓ 或 ⚠ 图标）；②模型卡片：模型名（Qwen3-4B / R1-Distill-Qwen-7B Q4，约 4GB）+ `一键下载` / 进度条 + 暂停继续 / 已下载`校验通过`标识 + `删除`按钮；③不达标态：按钮置灰 + 引导文案 + `使用在线模式`跳转；④下载切后台时系统通知栏显示进度（WorkManager）。

#### 5.6.4 业务逻辑

- **视角**：业务系统
- **描述方式**：
  1. 进入页面即调用系统 API 读取 RAM 总量与 SoC 型号，对照内置档位表（高层架构 V4：100% 下载前检测）给出"可运行 / 建议在线"结论；
  2. 达标 → 开放下载：WorkManager 后台任务分块下载（断点续传位点记录同 US-3），通知栏进度可见；
  3. 下载完成 SHA256 校验（同 US-3 逻辑），通过则模型状态"可用"，对话页离线档解锁；
  4. 不达标 → 下载按钮置灰 + 引导在线模式；用户强制尝试无入口（拦截在 UI 层与逻辑层双重生效）；
  5. 端侧推理经 JNI 桥接 llama.cpp，按 PocketPal 式加速降级链（CPU 为基线，GPU/NPU 可用则启用）运行。

#### 5.6.5 数据描述

| 数据项 | 流向 | 说明 |
| --- | --- | --- |

#### 5.6.6 验收标准 AC

- **AC-1（正常路径·达标机）**：Given 骁龙 8 系 + ≥ 8GB RAM 设备，When 进入 P-A5，Then 检测结论为"可流畅运行"，`一键下载`可用；下载完成校验通过；离线对话实测 ≥ 8 tok/s（V1）。
- **AC-2（正常路径·后台下载）**：Given 下载进行到 30%，When 用户切到后台 10 分钟，Then 下载不中断，通知栏可见进度，回前台后位点连续。
- **AC-3（降级路径·不达标机）**：Given 6GB RAM 中低端设备，When 进入 P-A5，Then 下载按钮置灰不可点，展示降级引导文案，`使用在线模式`按钮可跳转——全程无崩溃、无 OOM（V4：100% 触达）。
- **AC-4（异常路径·存储不足）**：Given 剩余存储不足 5GB，When 点击`一键下载`，Then 拦截并提示所需空间，建议清理后重试。
- **AC-5（异常路径·校验失败/续传）**：与 US-3 AC-2/AC-4 同标准（断点续传位点恢复；校验失败删除文件并提示重新下载）。

### 5.8 US-8：手机扫码配对电脑（F9）

#### 5.8.1 业务场景

- **视角**：用户（R3 手机端使用者，配合 R2 在电脑旁）
- **描述逻辑**：R3 第一次想让手机能遥控宿舍的电脑。电脑端打开远程控制面板点一下`生成配对码`，手机扫码（或手输 6 位码），60 秒内完成绑定，以后打开 App 就能看到这台电脑在线——不需要注册账号，配对关系即身份。

#### 5.8.2 业务流程

- **视角**：用户
- **描述方式**：
  - **Given** LocalMind 已启动且中继连通（P-W3 远程控制面板页）、LocalFile 已启动（P-A4 远程控制页，未配对态）
  - **When** R2 在电脑端点击`生成配对码`，R3 在手机端点击`扫码配对`对准屏幕二维码（或点`输入配对码`手输 6 位数字 + `连接`）
  - **Then** 手机端 60 秒内显示"配对成功"，进入已连接态（顶部设备卡片：电脑名 + 在线绿点 + 中继延迟）；电脑端已配对设备列表新增该手机（可重命名/解绑）

#### 5.8.3 UE 原型

页面：**P-W3 远程控制面板页** + **P-A4 远程控制页**。核心节点：①电脑端配对卡片：`生成配对码`按钮 → 6 位大字号配对码 + 二维码 + 5:00 倒计时 + `复制配对码`；②手机端未配对态：`扫码配对`（调相机）+ `输入配对码`（6 位数字键盘 + `连接`）；③已连接态设备卡片：电脑名、绿点、延迟 ms、`断开`；④电脑端设备列表：设备名、机型、最近在线、`重命名`/`解绑`。

#### 5.8.4 业务逻辑

- **视角**：业务系统
- **描述方式**：
  1. 电脑端向中继调度模块（RelayCloud）请求签发配对码：中继生成 6 位随机码，绑定电脑设备 ID，5 分钟 TTL + 一次性使用；
  2. 手机端输码/扫码（二维码内容为配对码字符串，不含任何密钥）→ 向中继提交配对码 + 本设备信息；
  3. 中继校验（存在性、未过期、未使用）→ 建立双向设备绑定关系，写入设备表，双方各获得对端设备 ID；
  4. 双端各自将绑定关系持久化到本地；之后双端上线经 WSS 互报在线状态；
  5. 解绑：任一端发起 → 中继删除绑定关系并通知对端；配对码过期/已用则签发侧可重新生成。

#### 5.8.5 数据描述

| 数据项 | 流向 | 说明 |
| --- | --- | --- |
| 配对码（6 位数字，5 分钟 TTL） | 中继 → 电脑端屏幕 → （人眼/扫码）→ 手机端 → 中继校验 | 一次性，用完即废；无密钥派生之外的敏感信息 |
| 设备绑定关系（电脑 ID ↔ 手机 ID + 设备名） | 中继设备表 + 双端本地存储 | 无账号体系，设备即身份（O3 边界） |
| 在线状态与延迟 | 双端 ↔ 中继（WSS 心跳） | 手机端设备卡片展示 |

#### 5.8.6 验收标准 AC

- **AC-1（正常路径）**：Given 双端在线，When 电脑生成配对码后手机在 5 分钟内完成扫码，Then 全流程 ≤ 60 秒（V2），双方界面均显示配对成功与对端设备名。
- **AC-2（手输路径）**：Given 扫码不可用（实例—相机权限被拒），When 用户选择`输入配对码`手输 6 位并点`连接`，Then 同样完成配对，体验时长相当。
- **AC-3（异常路径·过期码）**：Given 配对码已超 5 分钟，When 手机提交，Then 提示"配对码已过期，请在电脑端重新生成"，不建立任何绑定。
- **AC-4（异常路径·错误码/已用码）**：Given 输入不存在或已使用的配对码，When 提交，Then 提示"配对码无效"，允许重试且不产生绑定残留。
- **AC-5（解绑）**：Given 已配对设备，When 电脑端点击`解绑`，Then 双端绑定关系删除，手机端回到未配对态，中继设备表无残留记录。
- **AC-6（演示可靠性）**：Given 课程演示环境，When 连续进行 10 次配对+连接，Then 成功 ≥ 9 次（V2 指标）。

#### 5.8.7 外部集成接口

### 5.9 US-9：手机对话式远程控制电脑（F10 + F4 远程侧）

#### 5.9.1 业务场景

- **视角**：用户（R3 手机端使用者；R5 被控电脑在场者为受影响方）
- **描述逻辑**：R3 在教室上课，想起宿舍电脑里有一份没整理的下载文件夹。他打开 LocalFile 遥控 Tab，对电脑说一句"整理下载文件夹，把安装包移到 D 盘软件目录"。他希望 2 步内发出指令、实时看到"已发送→已送达→执行中→已完成"的状态流转，最后读到结果文本；若指令涉及删除等危险动作，电脑屏幕会弹确认窗，室友（R5）在场能当场拦截。

#### 5.9.2 业务流程

- **视角**：用户
- **描述方式**：
  - **Given** 手机与电脑已完成配对（US-8）、双端在线、电脑端`远程控制总开关`为开
  - **When** R3 在`指令输入框`输入"整理下载文件夹"并点击`发送`（或点`快捷指令`Chip）
  - **Then** 指令卡片出现并按"已发送→已送达→执行中→已完成"流转；完成后折叠区可展开结果文本；若命中危险动作，手机端显示"等待电脑端确认…"，电脑端弹窗 15 秒倒计时，允许后才继续执行；失败时状态徽标变红并附原因

#### 5.9.3 UE 原型

页面：**P-A4 远程控制页**（已连接态）+ **P-W3 二次确认弹窗**。核心节点：①顶部设备卡片（电脑名、绿点、延迟、`断开`）；②`指令输入框`（占位提示"想让电脑做什么？例如：打开浏览器并总结剪贴板"）+ `发送`；③`快捷指令`横滑 Chip 组（打开应用/锁屏/调音量/总结剪贴板/整理下载文件夹）；④指令状态列表（倒序）：状态徽标五态流转、结果文本折叠区、失败原因红字；⑤"等待电脑端确认…"同步状态；⑥电脑端确认弹窗（同 US-4 原型）。

#### 5.9.4 业务逻辑

- **视角**：业务系统
- **描述方式**：
  1. 手机端将自然语言指令封装为指令信封（id、动作意图原文、来源设备、时间戳），经 WSS 发往中继调度模块；
  2. 中继校验绑定关系与对端在线状态 → 路由下行至目标电脑（不在线则回"送达失败：电脑离线"）；
  3. 电脑端远程控制模块接收 → 对话引擎解析意图为结构化动作 → 白名单校验（同 US-4 逻辑）→ 危险动作触发本机二次确认（15 秒超时默认拒绝）；
  4. 执行结果（成功/失败 + 结果文本/错误原因）封装回执信封，经中继回传手机；
  5. 中继只中转不解析指令内容；状态机每一跳（送达/执行中/完成）都生成状态事件推回手机端；电脑端执行日志本地留痕（同 US-4）。

#### 5.9.5 数据描述

| 数据项 | 流向 | 说明 |
| --- | --- | --- |
| 指令信封（JSON 文本） | 手机 → 中继（WSS）→ 电脑 | MVP 纯文本信封；完整版同格式叠加 E2E 加密层（演进纪律） |
| 状态事件（五态） | 各跳节点 → 中继 → 手机 | 已发送（手机本地）→ 已送达（中继 ACK）→ 执行中（电脑 ACK）→ 已完成/失败 |
| 结果文本 / 错误原因 | 电脑 → 中继 → 手机 | 文本量级（KB 级），与视频流方案相比数据量小 2~3 个数量级（高层架构 §4.1） |
| 执行日志 | 电脑本地 | 含来源设备标识，供留痕与周度复盘（R5 关注点） |

#### 5.9.6 验收标准 AC

- **AC-1（正常路径）**：Given 已配对且双端在线，When 手机发出"总结剪贴板"指令，Then 状态按五态依次流转，端到端时延 P95 ≤ 3 s（不含模型生成耗时，N2），完成后结果文本可读；从打开 App 到发出指令 ≤ 2 步（已配对）。
- **AC-2（危险动作双端联动）**：Given 指令涉及文件删除，When 电脑端弹窗等待确认，Then 手机端同步显示"等待电脑端确认…"；电脑端点`拒绝`或超时后，手机端状态变"被拦截"并附说明；点`允许执行`则继续流转至完成。
- **AC-3（异常路径·电脑离线）**：Given 电脑端不在线，When 手机发出指令，Then 2 秒内收到"送达失败：电脑当前离线"，指令卡片标红，建议稍后重试。
- **AC-4（异常路径·白名单外）**：Given 指令解析后动作不在白名单，When 电脑端执行器校验，Then 拒绝执行，手机端收到"该操作不在电脑允许范围"，电脑端日志记"被拦截"。
- **AC-5（异常路径·中继断连）**：Given 指令已发送但中继连接中断，When 状态停留在"已发送"超过 5 秒，Then 手机端提示"连接中断，正在重连"，自动重连成功后续传；重连失败则标记失败。
- **AC-6（留痕一致）**：Given 一天内远程执行 ≥ 10 条指令，When 打开电脑端 P-W3 记录列表，Then 每条含时间、来源设备名、指令内容、状态，与手机端指令卡片一一对应。

#### 5.9.7 外部集成接口

| 依赖 | 内容 |
| --- | --- |
| RelayCloud 中继服务（WSS） | 指令路由、状态中转、在线状态表——自建（F11）；端到端时延预算 P95 ≤ 3 s 全部消耗在"手机→中继→电脑→中继→手机"链路与本机解析，不含模型生成 |
| Windows OS 能力 | 与 US-4 相同的本机执行依赖 |
| 无视频流依赖 | 结果仅文本回传（O1 边界）；完整版 F14 才增加截图单帧回传 |

### 5.10 US-10：低端 Android 机降级引导（F8 降级路径 · 场景强化）

#### 5.10.1 业务场景

- **视角**：用户（R3 手机端使用者，持 6GB RAM 中低端机型）
- **描述逻辑**：R3 的同学拿着一台 4~6GB RAM 的旧手机也想装 LocalFile 玩离线 AI。打开模型页后，应用应明确告诉他"这台设备建议用在线模式"，而不是让他下完 4GB 才发现跑不动、或者运行中直接闪退。降级路径必须 100% 触达且一次说清。

#### 5.10.2 业务流程

- **视角**：用户
- **描述方式**：
  - **Given** 一台 RAM ≤ 6GB 或 SoC 不在达标清单的 Android 设备，LocalFile 首次进入 P-A5
  - **When** 设备检测自动完成
  - **Then** 检测卡片显示 ⚠ 结论（实例—"6GB RAM，建议使用在线模式"）；`一键下载`置灰不可点；降级引导文案说明原因与替代方案；`使用在线模式`按钮一键跳转对话页在线模式；后续在对话页尝试切离线档时同样被拦截并解释

#### 5.10.3 UE 原型

页面：**P-A5 模型与设置页**（不达标态）。核心节点：①检测卡片 ⚠ 图标 + 原因文案；②模型卡片置灰态 + 引导文案；③`使用在线模式`跳转按钮（主按钮视觉）；④对话页离线档点击时 Toast/弹层解释并跳回 P-A5。

#### 5.10.4 业务逻辑

#### 5.11.5 数据描述

### 5.12 US-12：P2P 通道与桌面截图单帧回传（F14 · 完整版）

#### 5.12.1 业务场景

- **视角**：用户（R3 手机端使用者）
- **描述逻辑**：完整版阶段，R3 远程让电脑执行完操作后，想"看一眼"桌面确认效果（实例—整理后的文件夹窗口）。指令完成后电脑自动截取一帧桌面截图回传手机；同 Wi-Fi/可打洞环境下指令改走 WebRTC P2P 直连，时延更低、中继带宽更省——打洞失败则自动回落 WSS 中继，用户无感知。

#### 5.12.2 业务流程

- **视角**：用户
- **描述方式**：
  - **Given** 完整版双端、已配对、通道策略为"自动"（P2P 优先、中继兜底）
  - **When** R3 发出一条远程指令并执行完成（且用户在快捷指令或设置中启用了截图回传）
  - **Then** 指令卡片结果区除文本外附一帧桌面截图缩略图（点开看大图）；状态栏可见当前通道类型（直连/中继）；打洞失败时自动回落中继，流程与时延表现与 US-9 一致

#### 5.12.3 UE 原型

页面：P-A4 完整版扩展 + P-W3 设置项。核心节点：①指令卡片截图缩略图与大图查看；②通道类型标识（P2P 直连 / 中继）；③P-W3 截图回传开关（默认关，需用户显式开启）与白名单勾选项。

#### 5.12.4 业务逻辑

- **视角**：业务系统
- **描述方式**：
  1. 通道层升级：ICE/STUN 打洞，成功则建立 WebRTC DataChannel 直连传输指令信封（同 MVP 信封格式 + E2E 加密层）；失败回落 WSS 中继（MVP 骨架保留为兜底，演进纪律）；
  2. 截图回传：执行完成后由电脑端截取当前桌面单帧 → 压缩 → 经当前通道回传手机；截图动作本身纳入白名单与二次确认策略管控；
  3. 中继侧带宽消耗随 P2P 占比下降，纳入运营监控回路（V2 成本项）。

#### 5.12.5 数据描述

| 数据项 | 流向 | 说明 |
| --- | --- | --- |
| 指令信封（加密层） | P2P DataChannel 或中继回落 | E2E 加密时中继不可读（借鉴 RustDesk 零信任模式） |
| 截图单帧（压缩图） | 电脑 → 手机 | 仅单帧、仅用户开启时；不做视频流（O1 长期边界） |
| STUN/TURN 配置 | 预置 + 可自建 | TURN 为打洞失败的运营商级兜底（非常态流量） |

#### 5.12.6 验收标准 AC

- **AC-1（P2P 路径）**：Given 双端同 Wi-Fi，When 发出指令，Then 通道标识显示"直连"，端到端时延优于中继路径或相当。
- **AC-2（回落路径）**：Given 对称 NAT 打洞失败环境，When 发出指令，Then 自动回落中继，用户无感知，功能与时延满足 N2（P95 ≤ 3 s）。
- **AC-3（截图回传）**：Given 截图开关已开且指令执行完成，When 结果回传，Then 手机端收到清晰可辨的桌面单帧截图；开关关闭时无任何截图行为。
- **AC-4（异常路径·截图被拦截）**：Given 截图动作命中二次确认策略，When 电脑端弹窗超时/拒绝，Then 仅回传文本结果，手机端注明"截图未授权"。

#### 5.12.7 外部集成接口

| 依赖 | 内容 |
| --- | --- |
| STUN/TURN 服务 | 公共 STUN 或自建 TURN；云主机带宽预算内（V3 成本约束） |
| WebRTC（DataChannel） | 端侧库集成；仅数据通道，不涉及音视频 |

### 5.13 US-13：云端运维巡检与成本封顶（F12 看板 + V3 运营回路）

#### 5.13.1 业务场景

  4. 月度成本 = 云主机 + 对象存储/CDN + DeepSeek API 三项合计，人工核对（校级量级不引入自动报表，高层架构 §5.3 运营主线）。

### 6.4 安全性需求

> 满足校级项目小范围私有分发的安全基线；详细安全设计归 security-architect（Phase 5《安全设计》），本节仅从用户故事与产品需求角度回收安全要求。

#### 6.4.1 安全密码设置

- 本产品**无账号密码体系**（O3 边界：设备配对即身份），故无用户密码强度要求；
- 运维侧凭据（new-api 管理台、云控制台）由 R4 个人保管，要求满足 **8 位以上大小写字母 + 数字 + 特殊字符** 强度；
- 设备令牌由网关签发（高熵随机串），非用户自选，天然满足强度要求；令牌按设备粒度可吊销、可设月度额度上限。

#### 6.4.2 安全软件架构

- 双端与云端之间通信一律使用加密通道：在线对话走 HTTPS，远程控制走 WSS（TLS）；
- 客户端**零接触**真实 API key：key 仅存于网关配置，模型映射使客户端只见"Deepseek-V4-Pro"；安装包构建管线自动扫描，0 个 key 入包（V3/US-14 AC-3）；
- 远程指令通道以配对绑定关系为访问控制前提：未配对设备提交的指令一律拒绝；配对码 5 分钟 TTL + 一次性；
- 网关侧 100% 令牌带额度与速率上限，限制未经许可的接口访问与账单失控（V3）；
- 对象存储模型分发启用签名 URL 防盗链 + 下载次数限制，限制外部系统所能获取的内容。

#### 6.4.3 安全设计

- 认证授权：无用户账号体系，采用"设备绑定 + 令牌"双因子形态——远程控制以配对关系鉴权，在线 API 以设备令牌鉴权；
- 危险操作二次确认：远程/本机触发的危险动作必须经本机弹窗人工确认，15 秒超时默认拒绝，确认开关默认开启（US-4/US-9）；
- 指令白名单：执行器只执行白名单内动作，白名单外一律拒绝并留痕；白名单可由用户在 P-W3 收缩。

#### 6.4.4 安全开发

- 指令执行器对入口参数做合法性校验：动作类型枚举校验、路径参数防穿越（禁止白名单外目录）、参数长度上限；
- 文件处理模块对 SAF 读取内容做大小与格式边界检查，防止畸形文件导致解析崩溃；
- 配对码、令牌等安全相关随机数使用密码学安全随机源；
- 输入输出过滤：远程指令原文与结果文本在 UI 渲染前转义，防止注入式内容（实例—伪造的确认弹窗文案）；
- 禁止使用未经授权和验证的代码：仅引入 MIT/Apache-2.0 许可组件（llama.cpp、new-api 等），许可证文本随应用展示（P-W4 关于页）；
- 不遗留后门：远程控制总开关关闭即彻底断开中继连接，无隐藏的常驻远控通道。

#### 6.4.5 安全测试和部署

- 上线前对安装包做安全扫描（恶意特征 + key 泄露扫描）；
- 安全配置基线检查：网关令牌额度全覆盖核查、对象存储防盗链生效核查、配对码 TTL 生效核查；
- 安全功能测试：白名单拦截用例、二次确认超时拒绝用例、过期/错误配对码用例必须全部通过（对应 US-4/8/9 异常路径 AC）；
- 系统上线前不存在高危风险：无 key 泄露、无未授权指令执行路径、无默认弱凭据。

#### 6.4.6 数据安全

- **存储加密**：设备令牌、设备 ID 存于 OS 级安全存储（Windows DPAPI / Android Keystore 体系）；会话记录与执行日志存本地，云端不落盘对话内容；
- **传输加密**：HTTPS（在线对话）+ WSS（远程控制）全链路 TLS；完整版 P2P 通道叠加 E2E 加密（中继不可读，US-12）；
- **数据最小化**：无注册登录、无个人信息采集（设备 ID 为随机生成）；文件内容在用户选择离线模式时全程不出设备；
- **留痕与清除**：远程执行日志本机留痕可供复盘，用户可一键`清空记录`。
