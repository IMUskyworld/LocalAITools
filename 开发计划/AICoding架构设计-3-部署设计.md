## 1. 引言

### 1.1 适用范围与部署形态

- **适用系统范围**：LocalMind × LocalFile 双端协同智能工具三组件——LocalMind Windows 桌面助手（Tauri 2.x + React/TS + Rust，exe 分发）、LocalFile Android 文件处理/遥控器（Kotlin + Compose，apk 分发）、RelayCloud 云端中继与 API 网关（单台 2C4G 云主机 Docker Compose 编排 relay-server + new-api）。
- **目标部署形态**：**公有云轻量形态**（非私有化、非混合云）。云端全部运行单元落于境内单 Region 单台云主机（2 vCPU / 4GB / 60GB SSD / 5Mbps，单 AZ）；双端安装包经对象存储 + CDN 与代码托管平台 Release 渠道分发；模型 GGUF 文件经对象存储 + CDN 分发。
- **不在范围内**：企业私有化交付、多 Region 多活、K8s 集群编排、独立中间件（MQ / 缓存 / 独立数据库实例）——均与《系统设计》§5.1 部署形态及高层架构 D5 / O7 冻结决策一致。
- **读者对象**：兼职运维者（项目委托人兼任，单人运维）、双端与云端开发（1~5 人小团队）、安全架构师（security-architect）、G5 评审委员会。

## 2. 环境与资源清单

### 2.1 环境矩阵

> 模板要求四环境齐备。《系统设计》§5.1 已将云端成本冻结为"单台 2C4G、月账单 ≤ 150 元"，云端无法承载四套独立环境；本节以"**云端环境形态 × 隔离策略**"如实映射四环境职责，其中 int/uat 云端侧复用 prod 基础设施并以**逻辑隔离**（独立容器命名空间 / 独立 SQLite 文件 / 独立令牌分组）实现，不新增云资源、不突破成本红线。

| 环境 | 用途 | 集群隔离 | 数据 | 网络访问 | 云端落地形态 |
| --- | --- | --- | --- | --- | --- |
| dev | 双端 + 云端开发自测 | 共享（开发者本机，与 prod 物理隔离） | 模拟数据（本机 SQLite） | 内网（localhost / 局域网） | relay-server 本机进程 + new-api 本机 Docker；网关域名 `relay-dev.local`；dev 专用 DeepSeek 渠道（限额测试 key） |
| int | 双端真机联调（打包形态验证） | 逻辑隔离（prod 云主机上独立容器后缀 `-int`） | 模拟数据（独立 `relay-int.db`） | 内网 + 白名单（仅项目组设备 IP 段可连 8443 端口） | 云主机上 `docker-compose.int.yml` 拉起 relay-server-int / new-api-int，监听 8443（WSS）/ 8444（REST），共享 Nginx 不同 server_name |
| uat | 预发 / 验收（分发前最终验证） | 逻辑隔离（同主机独立卷与令牌分组） | 仿生产（脱敏造数的设备 / 配对 / 指令样本） | 内网 + 白名单（同 int；验收窗口期临时放行验收人员 IP） | 复用 prod 容器镜像 Tag，独立数据卷 `relay-uat.db`，独立 new-api 令牌分组 `uat-group`；验证完成后关闭窗口 |
| prod | 生产（≤ 50 用户小范围分发） | 独立（单台云主机全部资源专用 + 独立域名） | 真实数据 | 公网（443 唯一入口）+ 22 限运维固定 IP | relay-server / new-api / Nginx 三容器常驻；对象存储模型桶 + 备份桶；CDN 分发 |

### 4.2 CI/CD 流水线（8 阶段）

> 流水线平台：GitHub Actions（公开仓库免费额度）。三条流水线：LocalMind（Windows exe）、LocalFile（Android apk）、RelayCloud（云端镜像 + 部署）。

| 阶段 | LocalMind 流水线 | LocalFile 流水线 | RelayCloud 流水线 |
| --- | --- | --- | --- |
| 1. 触发 | push tag（v*）/ PR | push tag / PR | push tag / PR（relay-cloud/ 路径） |
| 2. 代码检查 | ESLint + cargo clippy + cargo fmt --check | ktlint + detekt + lint | cargo clippy + fmt（relay-server） |
| 3. 单元测试 | vitest（前端）+ cargo test（Rust） | JUnit + Compose UI test | cargo test（relay-server） |
| 4. 安全扫描 | cargo audit + npm audit | dependency-check（Gradle） | cargo audit + Trivy 镜像扫描 |
| 5. 构建 | `tauri build`（产出 exe + msi） | `./gradlew assembleRelease`（产出 apk） | `docker build` relay-server 镜像（锁 digest） |
| 6. 红线校验 | **构建产物扫描：0 个真实 key / 真实模型名（V3 红线，《安全设计》§8）** | 同左（apk 扫描） | 镜像 digest 记录 + SBOM 生成 |
| 7. 打包签名 | exe 安装包（NSIS，含 WebView2 引导）；产物 ≤ 80MB 校验（N1） | apk 签名（上传 keystore 至 CI Secret）；产物 ≤ 60MB 校验（N1） | 镜像推送至镜像仓库（tag + digest） |
| 8. 发布 / 部署 | GitHub Release 上传 exe + 对象存储备份；分发清单更新 | GitHub Release 上传 apk + 对象存储备份 | SSH 至云主机：`docker compose pull && up -d`（滚动更新，健康检查通过后切流） |

**CD 部署策略**：单实例滚动更新（非蓝绿/金丝雀——单机形态约束）；`docker compose up -d` 逐个服务更新，healthcheck 通过后继续；失败自动回滚至上一 digest（§6.1 回滚 SOP）。

### 4.3 部署拓扑与发布窗口

- **发布窗口**：低峰期（00:30-08:30，与 DeepSeek 错峰半价时段重合，兼顾成本）；远程控制中断对用户无通知成本（校级小范围）。
- **回滚触发**：healthcheck 连续 3 次失败 / 冒烟测试（WSS 连接 + 在线对话各 1 次）失败 → 自动回滚至上一镜像 digest。
- **冒烟测试**：部署后自动执行——WSS 连接建立、配对码签发、`/healthz` 200、new-api `/v1/models` 200（经网关令牌）。
